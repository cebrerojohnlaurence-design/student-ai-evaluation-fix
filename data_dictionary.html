Data Dictionary

This Data Dictionary provides specific details regarding the configuration and composition of the underlying database for the AI-Integrated Web-Based Student Grade Evaluation System. It documents each table, detailing its specific fields, corresponding data types, and primary function within the platform. The definitions in this section describe how the system maintains and organizes core data, including information on user roles, student metrics, academic results, and attendance records, enabling features like role-based access control, QR code integration, and intelligent student performance analytics.

Table 1: Users Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for each user
usernameVARCHARUser's login username
passwordVARCHAREncrypted password for authentication
roleVARCHARThe specific access level of the user (e.g., principal, coordinator, teacher)
statusVARCHARCurrent account status (e.g., active, inactive)
created_atTIMESTAMPDate and time the account was created

This table manages the core account information for anyone accessing the platform. It holds the primary login credentials and roles that allow the system to verify identities and provide a secure environment based on role-based access controls.

Table 2: Principals Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the principal record
user_idBIGINT(FK)Reference to the Users table
employee_idVARCHARProfessional identification number
first_nameVARCHARFirst name of the principal
last_nameVARCHARLast name of the principal

Stores the professional profiles of school principals, linking their administrative details to their system login credentials.

Table 3: Coordinators Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the coordinator
user_idBIGINT(FK)Reference to the Users table
employee_idVARCHARProfessional identification number
first_nameVARCHARFirst name of the coordinator
last_nameVARCHARLast name of the coordinator
departmentVARCHARThe specific department they coordinate (e.g., JHS, SHS)

Contains the profiles of curriculum coordinators, tracking their designated departments and linking to their main user account.

Table 4: Teachers Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the teacher record
user_idBIGINT(FK)Reference to the Users table
employee_idVARCHARProfessional ID number of the teacher
first_nameVARCHARFirst name of the teacher
last_nameVARCHARLast name of the teacher
departmentVARCHARThe department the teacher belongs to
is_adviserBOOLEANFlag indicating if the teacher handles an advisory class

Faculty profiles are organized here to link educators with their credentials. It identifies their specific department and highlights whether they are currently assigned as class advisers.

Table 5: Students Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for each student
user_idBIGINT(FK)Reference to the Users table
lrnVARCHARLearner Reference Number
first_nameVARCHARFirst name of the student
last_nameVARCHARLast name of the student
middle_initialVARCHARMiddle initial of the student
genderVARCHARGender of the student
birth_dateDATEDate of birth of the student

The primary details for every enrolled learner are stored in this registry. It captures the identity of the student alongside their unique LRN, which is essential for managing academic data and utilizing the QR-based entry features of the system.

Table 6: Subjects Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the subject
codeVARCHARUnique subject code
nameVARCHARDescriptive name of the subject
grade_levelVARCHARThe grade level this subject belongs to
typeVARCHARCategory of the subject (e.g., core, applied)

This catalog stores all the academic subjects offered by the school, categorized efficiently by their specific grade level and curriculum type.

Table 7: Sections Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the class section
nameVARCHARName of the section (e.g., Emerald)
grade_levelVARCHARThe grade level for this section
school_yearVARCHARThe academic year of the section
adviser_idBIGINT(FK)Reference to the assigned advisory teacher

Manages the class sections created for each academic year. It associates a specific grade level with each section and assigns a dedicated teacher as the class adviser.

Table 8: Section Subjects Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the record
section_idBIGINT(FK)Reference to the Sections table
subject_idBIGINT(FK)Reference to the Subjects table
teacher_idBIGINT(FK)Reference to the assigned Teacher

A mapping table that explicitly defines the class schedule by assigning which teacher is responsible for teaching a specific subject within a particular class section.

Table 9: Enrollments Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the enrollment record
student_idBIGINT(FK)Reference to the Student
section_idBIGINT(FK)Reference to the assigned Section
school_yearVARCHARThe academic year of enrollment
statusVARCHARCurrent enrollment status (e.g., Enrolled, Dropped)

Records the enrollment history of students, successfully grouping them into specific class sections for a given school year to monitor their academic journey.

Table 10: Grades Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the grade record
student_idBIGINT(FK)Reference to the Student
subject_idBIGINT(FK)Reference to the Subject
section_idBIGINT(FK)Reference to the Section
quarterINTThe grading quarter (e.g., 1, 2, 3, 4)
written_scoreDECIMALTotal score for written works
performance_scoreDECIMALTotal score for performance tasks
assessment_scoreDECIMALTotal score for quarterly assessments
final_gradeDECIMALComputed final grade for the quarter

This table acts as the system's E-Class Record, tracking the specific academic progress of students. By archiving a detailed breakdown of written works, performance outputs, and exam results, it provides the necessary data points for the system to compute final quarterly grades automatically.

Table 11: Attendances Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the attendance record
student_idBIGINT(FK)Reference to the Student
section_idBIGINT(FK)Reference to the Section
dateDATEThe specific date of the record
statusVARCHARAttendance status (e.g., Present, Absent)

Tracks the daily or weekly attendance of students within their assigned sections to maintain compliance and help identify chronic absenteeism early.

Table 12: Activity Logs Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the log entry
user_idBIGINT(FK)Reference to the User who performed the action
actionVARCHARThe specific action performed
descriptionTEXTDetailed description of the event
created_atTIMESTAMPExact date and time of the action

Provides a comprehensive audit trail of all system actions. It allows administrators to securely monitor user activity, track modifications, and maintain high accountability across the platform.

Table 13: AI Predictions Table

Field NameData TypeDescription
idBIGINT(PK)Unique identifier for the prediction record
student_idBIGINT(FK)Reference to the Student evaluated
risk_levelVARCHARCategorized risk level (e.g., High, Low)
factorsTEXTKey variables that triggered the prediction
recommendationTEXTSuggested academic intervention
generated_atTIMESTAMPDate and time the prediction was generated

Stores the output and insights generated from the Random Forest machine learning model. It identifies at-risk students and provides actionable transparency (such as risk factors and recommendations) for targeted academic interventions.
